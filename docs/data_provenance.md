# Logistics data provenance

This project distinguishes inherited supplier-graph evidence, source-backed port records, historical vessel movement evidence, and modeled logistics assumptions. Port and service source files are generated by the ingestion/build scripts and accompanied by manifests; no commercial liner schedule or quotation is present.

## Sources and limitations

| Source | Fields/records | License/version | Caveat |
|---|---|---|---|
| AlMahri `dataset/supplychainKG_clean.csv` (`../almahri-upstream/dataset/supplychainKG_clean.csv` in this environment) | Company names, industries, countries, direct supplier/customer edges | Upstream repository: https://github.com/sara-almahri/supply-chain-disruption-monitoring; license/version must be confirmed from the upstream checkout before redistribution | `suppliesTo` is inherited relationship evidence, not a transaction, facility, or shipment |
| `src/maritime/network.py` pilot `COUNTRY_PORT`/`HUB_LINKS` | Synthetic-dev gateway mapping, candidate services, time and cost | Local pilot source, versioned with this project | Deliberately modeled; no commercial schedule/service evidence |
| `data/reference/service_connections.csv` | `build_service_network.py` output | SeaRoute 1.6.0 plus `config/maritime_network.json`; build seed 42 | Explicitly modeled corridors; never interpreted as observed bookable services |
| UNECE UN/LOCODE | `data/reference/ports.csv`, filtered by selected AlMahri country coverage, maritime function, and published coordinates | Production release 2025-1, retrieved 2026-10-31; CC BY 4.0 | UN/LOCODE provides coded locations and coordinates, not verified supplier facilities or commercial service schedules. Coordinates are published to minute precision. |

Official publication/download page: <https://unlocode.unece.org/publications/>. The 2025-1 production archive used for ingestion is <https://opensource.unicc.org/un/unece/uncefact/vocab-locode/-/jobs/artifacts/2025-1/download?job=package-release>. UNECE documents the CSV's 12-column, headerless layout and degrees/minutes coordinate encoding at <https://unlocode.unece.org/docs/data-attributes/>. The retrieved archive SHA-256 and retrieval date are in `data/reference/ports_ingestion_manifest.json`.

## Field-level provenance matrix

| Field | Provenance | Classification |
|---|---|---|
| `supplier`, `customer`, country, industry, `supplier_edge_id` | Exact normalized columns/row from AlMahri CSV; edge ID is a deterministic hash of those fields | Inherited source data / derived identifier |
| `origin_location_assumption`, `destination_location_assumption` | Country names mapped to a gateway for the pilot | Modeled assumption; not a facility location |
| Port name/country/coordinates | Strict mode reference CSV; synthetic-dev names/countries from `COUNTRY_PORT` | Reference only when verified source is supplied; otherwise modeled; coordinates remain null |
| Service IDs, direction, transit, costs | Strict mode supplied reference CSV or synthetic-dev `HUB_LINKS` | Reference claim only with evidence; synthetic in dev mode |
| Shipment, cargo, release/deadline, route plan | Deterministic generator | Synthetic |
| Manifest checksum, seed, counts | Builder over exact input bytes and generated records | Derived provenance |

No verified supplier facilities, liner routes, schedules, cargo constraints, or independent recovery truth are included. Port-level gateways do not identify factory or warehouse coordinates.
